**明文只发一次，权限按最小给，停和删立刻生效** —— 新建令牌时那句「请立即复制保存」不是客气话：关掉弹窗之后，页面和接口里就只剩一个前缀，复制不到就只能重建一条。

## 场景

后台「令牌管理」页（`admin-web/src/views/api-key/index.vue`）：列表 名称 / 密钥前缀 / 权限 / 有效期 / 状态 / 最后使用 / 操作（编辑 / 删除），行内一个启用-禁用开关，页头「新增令牌」。

新增弹窗：名称、权限勾选（按域分读与写）、有效期（快捷 7 天或精确到分秒，也可永不过期）。提交成功后弹「令牌创建成功」——**明文就在这一屏里**，带一个「复制」和一个「我已保存，关闭」。

## 撑不住的时候

**① 明文只出现一次，这是设计而不是疏忽。** 库里存的是哈希，接口从不回读明文，列表只给前缀。它换来的是「库被拖走也拿不到可用的钥匙」，代价是「人没复制就等于没拿到」。这两件事必须同时说清，否则第一次用的人会以为关掉弹窗还能再看见。

**② AI 手里那把钥匙不能自己长权限。** 一条能管理密钥的 key，就等于能给自己勾上任何权限；一条能管管理员的 key，就等于能凭空造一个管理员。所以这两件事不是「敏感操作」，是**授权体系的自毁开关** —— 直接不给，而不是靠「小心点」。

## 规矩落在哪

① **创建**：填名称 + 勾权限 + 设有效期 → 返回明文（形如 `ak_` + 64 位十六进制，共 67 字符）→ 弹窗里可复制（`navigator.clipboard`，headless 下要先授权）→ 关闭后弹窗 `destroy-on-close`，明文节点从 DOM 里消失。

② **列表只给前缀**：展示形如 `ak_1a2b3…`，等于后端返回的 `keyPrefix`，长度远短于明文（用例断言 `< 20`），且它确实是明文的前几位。

③ **权限按域勾**：订单 / 商品 / 会员 / 配置 各有读与写，概览只有读。落库是数组，接口回读按排序比对。改权限是「整组覆盖」，会后端复核。

④ **有效期二选一**：「永不过期」或精确到分秒；快捷 7 天按钮把值填成 `yyyy-MM-dd HH:mm:ss`。到点自动失效，不需要人工操作。

⑤ **停用即失效、启用即恢复**：行内开关 `status 1↔0`。禁用后同一把 key 下一次调用立刻 401「API Key 无效或已过期」；重新启用又恢复 200。

⑥ **删除不可恢复**：行内删除 → 确认框（点名这把令牌）→ toast「已删除」→ 同一把 key 立即 401，列表里也搜不到。

⑦ **每次调用记最后使用时间**：有效调用后写回 `lastUsedAt`（同一 key 60 秒内只写一次，避免每次调用都写库），页面上那一列从「从未使用」变成时间。

⑧ **两条红线**：`/admin/api-keys` 与 `/admin/admins` 对任何 API Key 一律 403。而且红线判在**密钥有效性之前** —— 一把已经删掉的 key 去读密钥管理，拿到的仍是 403 而不是 401。

## 凭什么证明好了

`e2e/tests/scenarios/业务/AI集成/令牌管理.spec.js`，一条用例把密钥从生到死走完，每一步都真点页面、真拿这把 key 去调接口（`X-Api-Key`，不带任何 JWT）：

① 建令牌（勾「订单-读」「商品-读」、**故意不勾「商品-写」**、设 7 天）→ 明文匹配 `^ak_[0-9a-f]{64}$` → 复制到剪贴板的内容就是它 → 关闭后**页面任何可见文本里都没有明文**、明文节点 `count = 0`、列表只显示前缀且前缀等于服务端 `keyPrefix`。
② 用这把 key 调 `GET /admin/orders` → **200**，`lastUsedAt` 从此非空，刷新页面那列不再是「从未使用」。
③ 同一把 key 去 `POST /admin/products`（商品-写没勾）→ **403**，message 含 `catalog:write`。
④ 页面上补勾「商品-写」→ 同一个请求 **200** 并真建出商品（随后用商品列表的行内删除 + 高危确认弹窗把它删掉还原）。
⑤ 点禁用 → 同一把 key 调订单列表 → **401**「API Key 无效或已过期」，服务端 `status=0`。
⑥ 重新启用 → 又 **200**，`status=1`。
⑦ 行内删除 + 确认框 → **401**，列表与接口都查不到；再拿这把死 key 读密钥管理 → 仍 **403**（红线先于有效性）。
⑧ 红线：读 `/admin/api-keys` → 403 含「禁止访问」；读 `/admin/admins` → 403 含「管理员账号」。

用例跑完打一行证据：每一步的实测响应码 + 列表显示的前缀 + 明文长度（不回显明文）。

## 附：口径与边界

- **页面上勾不到四个只读域**：后端 `ALL_SCOPES` 有 13 个（多出 `ledger:read` / `stock:read` / `audit:read` / `channel:read`），但这一页的勾选框只渲染 9 个。所以「给 AI 只读台账 / 库存 / 审核 / 渠道」这件事，现在没有页面入口，只能走接口。详见「工具能力矩阵」页。
- **写 scope 里有四个刻意不存在**：`audit:write` / `stock:write` / `ledger:write` / `channel:write` 不在 `ALL_SCOPES` 里 —— 谁也勾不到，所以「AI 触发审核 / 解锁订单 / 重放渠道回调」对任何 key 都是 fail-closed。
- **停用不解已验证的会话**：被禁用的是 key 的**下一次**调用，不是正在处理中的请求。
- **最后使用时间有 60 秒节流**：同一 key 60 秒内多次调用只写一次，所以「刚调完立刻看」可能仍是旧时间（首次调用除外，用例只断言首次）。
- **删除后不可恢复**：没有回收站，要再用只能新建一条 —— 这也意味着「删了才发现没记下来」是无法补救的。
- **本页数字出处**：明文格式与 67 字符来自 `AiApiKeyService`（`ak_` 前缀 + 32 字节 = 64 位十六进制）；`status 0/1`、`keyPrefix`、`lastUsedAt` 与 60 秒节流来自同类的 `TOUCH_INTERVAL_MILLIS`；三句 401/403 文案来自 `ApiKeyAuthFilter`；「9 个勾选框」来自 `api-key/index.vue` 的 `SCOPE_OPTIONS`；前端 14 个静态 testid + 2 类动态 testid 来自 spec 的口径说明。
