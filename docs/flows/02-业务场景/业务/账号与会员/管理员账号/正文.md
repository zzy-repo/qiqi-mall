**账号能加、能停，但最高那个永远删不掉** —— 内置 `admin` 前端先拦一句「系统内置账号不可删除」，就算绕到接口，后端也拒绝删。这条规矩的意义不在保护一个账号，在于**没有任何人能把系统里最后一个能做主的账号删掉**。

## 场景

后台「管理员」页（`admin-web/src/views/admin/index.vue`）：列表 登录名 / 昵称 / 邮箱 / 状态，行内 编辑 / 删除，页头 新增。

新增填登录名、密码、昵称、邮箱；编辑时密码框留空表示不改。演示数据里第一行是 `admin`，昵称「超级管理员」。

## 撑不住的时候

**① 停用之后必须只回「用户名或密码错误」。** 如果提示「该账号已被停用」，就等于告诉外人「这个名字存在，只是被关了」—— 顺着这条线索去猜密码，等于白送了半个答案。所以停用与密码错在对外表现上必须一模一样。

**② 内置账号删掉了没有兜底。** 谁能删掉 `admin`，谁就能让整个后台再没人能建管理员 —— 这不是权限问题，是把系统的恢复能力一起删了。

**③ 密码一旦回显就是事故。** 列表和详情接口从不回读密码，编辑时也不回填；`BCrypt` 只往库里写。所以「编辑时密码留空 = 不改密码」必须先被证明一次（不然没人知道留空到底有没有把密码写空）。

## 规矩落在哪

① **登录名唯一**：`username` 有唯一键。重名保存后端拒，页面红 toast「保存失败」、弹窗保持打开（不是悄悄关掉）。

② **必填在前端就地拦**：空登录名 → 「请输入登录名」；新增时密码为空 → 「请输入密码」。拦截后弹窗不关、不保存。

③ **密码只写不读、留空不改**：新增必填；编辑留空走「不改密码」分支。用例专门验证了「编辑（密码留空）后原密码仍能登录」。

④ **禁用 = 停得住**：`status=0` 的账号登录返回 401「用户名或密码错误」（与密码错同文案，见上）。

⑤ **删除两侧都拦内置账号**：前端 `admin/index.vue` 先判 `username === 'admin'`，弹一句黄条「系统内置账号不可删除」、**连确认框都不弹**；后端 `AdminController.delete` 同样先判，回「系统内置账号不可删除」。删自建账号是行内「删除」→ `ElMessageBox` 确认 → toast「已删除」→ 该账号立即登录失败。

⑥ **删除的是账号，不是它的痕迹**：审核、删单、发货这些动作在后台操作审计里记的是 `target/operator` 快照，账号删了历史仍在。

`e2e/tests/scenarios/业务/账号与会员/管理员账号.spec.js`，1 条用例 9 步（覆盖完整生命周期 + 四类边界）：

① 列表里能看到内置 `admin`，且那行标着「超级管理员」。
② 新增（用户名 / 密码 / 昵称 / 邮箱）→ toast「保存成功」、列表多一行。
③ **用新账号真登录一次**（独立浏览器上下文）→ 真的进了后台。这一步是「账号可用」的唯一硬证据，不是靠列表里有一行推出来的。
④ 编辑改昵称与邮箱 → 列表与只读接口都更新；**编辑不改密码 → 原密码仍能登录**。
⑤ 行内删除 → 确认框 → toast「已删除」→ 列表少一行 → **用这个账号登录失败**。
⑥ 边界A：用户名填 `admin` 造重名 → 红 toast「保存失败」、弹窗仍开着。
⑦ 边界B：空登录名 → 「请输入登录名」；空密码 → 「请输入密码」。
⑧ 边界C：新建一个 `status=0` 的账号 → 列表显示「禁用」→ 登录失败且响应体是「用户名或密码错误」。
⑨ 边界D：对内置 `admin` 点删除 → toast「系统内置账号不可删除」→ **页面上没有确认框**（`.el-message-box` 数量为 0）→ `admin` 仍在列表。

## 附：口径与边界

- **内置账号的判据是用户名等于 `admin`（忽略大小写）**，不是某个 id 或某个 `is_builtin` 字段。所以「内置」这件事没有数据支撑，只有一行代码判断 —— 改用户名就能绕过这条保护（后端 `AdminController` 的注释与实现都是这个口径）。
- **错误密码只打自建账号**：失败计数按用户名、5 分钟窗口、全局共享（见「管理员登录与验证码」页）。所以本页所有「登录失败」都发生在 `e2e_` 系的自建账号上，`admin` 全程只成功、绝不对它做失败登录 —— 否则会把共享登录态打进「需要验证码」。
- **停用不影响已登录的会话**：token 未失效，下一次登录才被拒。
- **没有角色 / 权限分级**：所有管理员进后台看到的是同一套菜单与能力，这一页只管「能不能进」，不管「进来能做什么」。
- **本页数字出处**：两端的内置账号文案来自 `admin/index.vue` 与 `AdminController#delete`；必填两条与「保存失败」来自表单规则与 `save` 的失败分支；「密码不回读」来自 `AdminController` 的列表/详情实现与 spec 的断言。管理员条数随演示数据漂移，正文不写具体人数。
