**后台能建会员，但建出来的号登不进商城** —— 新增弹窗里没有密码字段，`member.password` 落库是空串，登录遇到空密码直接判「用户名或密码错误」。真正能登录的账号只有一条来路：C 端注册。这一页的价值不在「管账号」，在**查得清**：两个子页各查各的，客服不用再让买家报订单号。

## 场景

后台 `admin-web/src/views/member/index.vue`：列表列 登录名 / 昵称 / 手机号 / 状态 / 注册时间，行内三个入口 —— **收货地址 / 购物车 / 编辑**。

两个子页是独立路由：`/member/:id/addresses` 与 `/member/:id/carts`，标题带会员登录名，进去只看得到这一个会员的数据。客服的典型用法就在这儿：买家说「我地址填错了」，点进地址子页直接改，不用问订单号。

## 撑不住的时候

**① 那三个入口里没有「删除」，也没有「详情」。** 操作列只有地址 / 购物车 / 编辑 —— 删除只能走接口（`DELETE /admin/members/{id}`）。把它当成「页面上点一下就行」，会让人在界面上找半天。

**② 删除的拦截不是业务守卫算出来的，是外键。** `MemberController.delete` 就一句 `removeById`，没有「数一下这人名下有多少订单」的逻辑。真正拦住它的是数据库：`order.member_id` 与 `return_apply.member_id` 都是普通外键（NO ACTION），于是删不掉，异常被统一翻成「数据被其它记录引用，无法删除（请先处理关联的物流、退货、明细等记录）」。**这句话是通用提示，不会告诉你是几笔订单还是几条退货申请。**

**③ 但「地址与购物车一并删掉」是真的**：`cart.member_id` 与 `member_address.member_id` 都是 `ON DELETE CASCADE`。所以一个名下干净的空账号删掉时，地址和购物车确实一起没了 —— 这条不是文案，是约束。

## 规矩落在哪

① **登录名唯一**：`uk_member_username`。重名保存后端拒，页面红 toast「已存在相同记录」，弹窗不关、列表不多行。

② **必填在前端就地拦**：登录名留空 → 「请输入登录名」，不提交、弹窗不关。

③ **改昵称不影响登录**：登录认的是 `username`，昵称只是展示。用例把「后台改昵称 → C 端退出用原密码重登」跑成了闭环。

④ **禁用 = 停得住，但只回一句通用错误**：`status=0` 后 C 端登录被拒，提示仍是「用户名或密码错误」，不提示「账号已被禁用」。外人猜不出账号存不存在 —— 这是有意的，代价是本人也不知道是被停用还是密码错了。

⑤ **密码只写不读**：接口从不返回 `password` 字段（用例断言 `m.password === undefined`），库里存 BCrypt。

⑥ **超长就地截断**：登录名 / 昵称 `maxlength=50`、手机号 `20`，输入时截断，不报错不拦截保存。

⑦ **编辑带版本号**：`PUT` 必须带 `version`，缺 → 400，被别人改过 → 409。`status` 也是并发敏感字段（禁用被覆盖 = 有人被错误放行），所以这里同样不允许「无版本校验」的更新。

## 凭什么证明好了

`e2e/tests/scenarios/业务/账号与会员/会员管理.spec.js`，4 条用例：

- **列表 + 地址子页**：C 端注册的会员在后台列表可见且默认「启用」；地址子页标题带登录名、行数与该会员地址数一致；另一个没建过地址的会员，子页显示「暂无数据」（**看不到别人的地址**）；聚合详情接口里这个会员 `addresses` 有 1 条、`carts` 为 0。
- **购物车子页**：同理，只看得到自己的购物车；没加过购的会员子页是空的。
- **新增 → 重名 → 空必填 → 编辑 → 禁用 → 删除**：新增弹窗**没有密码字段**（断言 `false`）；重名 toast「已存在相同记录」且行数不变；空登录名提示「请输入登录名」；编辑后昵称列逐格比对只剩新昵称；超长截断到 50 / 20 且服务端也一致；禁用后 `status=0`；删完列表行数回到新增前、接口也查不到。
- **账号可用性五步**：C 端注册 → 后台可见并可改昵称 → C 端用原密码仍能登录（且看到的是改后的昵称）→ 后台禁用后登录被拒且停在 `/login` → 恢复启用后又能登录。

## 附：口径与边界

- **「后台建的会员登不进」是刻意的现状，不是缺陷单**：`member.password` 是 `NOT NULL DEFAULT ''`，DDL 注释写着「登录功能未实现，新增时暂为空」。用例把它当**现状断言**（登录必然失败），而不是漏测。要能登录，只能走 C 端注册（那条路会 BCrypt 入库）。
- **删除拒因里不含「订单」或「退货申请」字样**：它来自 `GlobalExceptionHandler` 对 `DataIntegrityViolationException` 的统一翻译，句尾那句「请先处理关联的物流、退货、明细等记录」是通用枚举，不是按这一页算出来的。想知道具体是哪些单，只能自己去查。
- **「页面无删除入口」是 spec 显式记录的事实**：`support/admin-ui-member.js` 里的 `deleteMemberApi` 自带「页面无入口」的自查说明，删除断言靠接口 + 真实 reload 列表。
- **禁用不解 token**：C 端已登录的会话不会被立刻踢掉，下一次登录才会被拒。
- **本页数字出处**：字段与文案来自 `member/index.vue` 与 `MemberController`；`uk_member_username`、三条外键（`order`/`return_apply` NO ACTION、`cart`/`member_address` CASCADE）来自 `sql/schema.sql`；`maxlength 50 / 20` 来自表单渲染；「没有密码字段」来自 spec 对弹窗的断言。会员条数随演示数据漂移，正文不写具体人数。
