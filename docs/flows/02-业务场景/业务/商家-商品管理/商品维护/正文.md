**上下架管「卖不卖」，删除管「能不能消失」** —— 这两件事挤在同一张商品列表上，门槛却完全不同：下架只改一个字段、随时可逆；删除要过引用守卫，被订单明细引用过的商品**永远删不掉**，只能改成下架。

## 场景

后台 `admin-web/src/views/product/index.vue`：列表列 名称 / 分类 / 类型 / 上下架 / 主图 / 操作（编辑 / SKU / 删除）。

新增与编辑是同一个弹窗：名称、描述、分类（树选择器）、类型（下拉）、上下架（单选 上架 / 下架）、主图、相册（多行，每行一个图片地址 + 一个排序号）。相册的排序号决定买家看到的顺序 —— 不是上传的先后。

## 撑不住的时候

**① 删商品会牵走别人的证据。** 订单明细里存着商品 id。商品一删，历史订单的明细就指向空 —— 那张单还挂在「已完成」，但明细说不清买的是什么。所以这条边界不是「小心点」，是「不许」：被订单明细引用过的商品永远走删除失败这条路，出路是下架。

**② 删除是级联的，不先说清就会误删。** 删一个商品会连带删掉它下面的 SKU 和整组相册。这些不写在确认框里，用户点是「删一个没用的空商品」还是「删一个带 4 个 SKU 的」，事后没法分辨。

**③ 原来的删除连「为什么不行」都给不出。** 五个删除接口都直接 `removeById`，被引用时外键异常被兜底成「数据处理失败，请稍后重试」—— 用户分不清是网抖了还是被引用了。

## 改了什么

① **上下架就是 `publishStatus` 一个字段，C 端两道门都看它**：列表接口 `eq(Product::getPublishStatus, 1)`，详情接口 `product == null || publishStatus != 1` → 「商品不存在或已下架」。下架后列表与搜索立刻看不到，直接拿链接开详情也拿不到内容 —— 前端没有「缓存兜底」这一层。

② **删除改成「预演 → 确认 → 执行」三段**。`DELETE /admin/products/{id}?dryRun=true` 只算不落库，文案自动拼出会连带删掉什么：「将删除商品「X」（id=N），下辖 N 个 SKU 与相册一并删除。当前被 N 条订单明细、N 个购物车引用」；其中被引用时后半句直接改成「—— 删除会被拒绝，建议改为下架。」于是**预演永远 code=0、前端只有一条渲染路径**（不用为「预演被拒」写第二个分支）。

③ **真实拦截在后端，且分两种情况**：有订单明细 → 「该商品已被 N 条订单明细引用，不能删除（可改为下架）」；只在购物车里 → 「该商品还在 N 个买家的购物车里，不能删除（可改为下架）」。校验顺序是 **① 存在性 → ② 引用数守卫 → ③ 执行**。

④ **编辑走乐观锁 fail-closed**：缺 `version` → 400「缺少版本号，请刷新页面后重试」；UPDATE 影响 0 行 → 409，且因为「整组替换相册」排在更新之后，冲突时相册也不会被动。新建即 `version = 0`。

⑤ **相册整组替换**，`sort` 为空就按传入顺序补号（`++index`），库里按 `sort, id` 升序返回。

- **新增 → 编辑**：主图与描述落库对得上，详情接口回 `gallery` 恰好 2 张且 `sort` 升序 `[1,2]`；C 端详情页名称、描述、主图都能看到（图片按 `naturalWidth > 0` 判定真加载，不是只看 `<img>` 在不在）。

## 附：口径与边界

- **预演与真删是同一套守卫的两个入口**：预演先把结论说出来（会删什么、会被拒），真删再拦一次。所以「预演说会被拒」这件事本身就是证据的一部分。
- **购物车引用也算硬拦**：`CatalogDeleteGuard` 的注释里写了两句不同的话 —— 商品被订单明细引用时提示「改成下架」（历史订单必须追溯）；购物车引用哲学上是临时数据（顺手清掉更合理），但实现上仍拦，避免用户困惑。这是口径与实现的一处有意识的不一致，记在这里。
- **下架不影响已有订单**：订单明细存的是下单时的商品与价格快照，下架只改 C 端可见性。
- **相册排序是「展示顺序」不是「主图顺序」**：主图是单独的 `pic` 字段。
- **本页数字出处**：删除文案两条来自 `CatalogDeleteGuard#checkProduct`，预演句式来自 `ProductController#delete` 的字符串拼接；`sort` 补号来自 `saveGallery`；「版本号缺 → 400 / 0 行 → 409」来自 `ProductController#update` 与 `OptimisticLockGuard`。用例里 `gallery` 的 `[1,2]` 是当次运行造出来的两条，不是全局常量。
