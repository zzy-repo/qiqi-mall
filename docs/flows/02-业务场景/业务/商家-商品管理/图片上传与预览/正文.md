## 图片上传与预览（image upload）

主图、相册、SKU 图三处入口一个实现（`ImageUploader.vue`），后端是 `POST /admin/upload/image`，与商品提交解耦：图先落对象存储，商品保不保存是后面的事。同类里还挂着 `image-from-url`，给 AI 补商品图用：模型产不出 5MB 的 base64，也不该把服务器本地路径当上传通道，所以由后端按 URL 自己拉，SSRF 防护在 `MinioStorageService#fetchFromUrl`（只许 https、禁内网与重定向）。

拦截分两处。前端 `beforeUpload` 先挡：类型限 `image/jpeg` / `image/png` / `image/webp`，超过 5MB 不收，`accept` 同步写死，提示「仅支持 jpg / png / webp」与「图片不能超过 5MB」；前端挡是为体验，不让人白等。后端再挡一次，因为前端能绕过（直接打接口或换客户端），而且给的是真 HTTP 状态码而不是 200 加业务码：文件为空 400、超限 413、类型不在白名单 415、未登录 401。

落库的是相对路径：objectKey 是 `products/<yyyy>/<MM>/<uuid>.<ext>`，写入键再拼对象前缀，所以返回与入库都是 `/qiqi-mall/products/…` 这种形状；一旦把内网绝对地址落进库，换环境、换域名整站商品图集体 404，而那些字段不报错，只有人眼能发现。传完立刻看得见：返回 `{url, objectName}`，前端回填并渲染 72×72 预览；预览真不真看能否解码（`naturalWidth > 0`），不看 input 里有没有字符串。相册每行一个 `sort`，保存按 `sort, id` 升序落库与返回。

**验证**　`图片上传与预览.spec.js`：4 条用例，真点界面 + 读库 + 直打接口。主图全链路：点「上传」→ `filechooser` 接管系统文件框 → 预览图 `naturalWidth > 0` → 字段回填地址匹配 `^/qiqi-mall/` → 保存 → 库里 `pic` 就是它 → 该地址 `GET` 回来 200 且 `content-type` 含 `image/`。三道边界一次跑完：未登录 401；`text/plain` 415 且 message 含 `jpg`；5.5MB 真 413 且含 `5MB`；最后传一张正常小图 200 且 `data.url` 匹配 `^/qiqi-mall/`（反向确认，防止因别的故障恰好通过）。相册多图排序：加 3 张、排序改 3 / 2 / 1 → 库里 `sort` 是 `[1,2,3]`，而 `sort=1` 对应最后添加那张；C 端相册 `src` 顺序与库里一致且每张真加载。SKU 图与回退：后台 SKU 列表缩略图真渲染；C 端切到配图规格 → 主图正是那张 SKU 图；切到没配图的 → 回退成商品主图。

**边界**　「超 5MB 能打到后端」有前提：multipart 5MB、nginx 6m，5.5MB 能穿过网关进到 Controller 才拿到 413，再大被网关挡住，看到的不是这套文案。上传不校验商品是否已保存：取消弹窗后存储里会留下没人引用的对象，没有清理任务。没有压缩、缩略图与格式转换：传什么存什么，5MB 的图上了首页还是 5MB。SKU 图回退不是合并：只在「这个 SKU 没 `pic`」时用商品主图顶上；「点缩略图」能盖过规格图是相册（SPU 级）的优先级，不是回退。已录视频里没有被拒画面：那三道校验的证据是接口级 401 / 415 / 413，界面点不出「选 5MB 以上文件」这一步，要录到拒绝帧得走 `filechooser` 塞超限文件。
