**商品类型与属性是同一个聚合的两层，属性不归全局字典** —— 先建类型（手机、食品），再在那个类型下挂属性（颜色、内存）；属性页只认一个 typeId，看不见别的类型下的属性。两层各有一条删不掉的边界：类型被属性或商品引用、属性被 SKU 规格值用到，都拒删，并把「还剩几个」说清。

## 场景

后台两个页面：`admin-web/src/views/product-type/index.vue` 是类型列表，行内「编辑」「属性」「删除」；点「属性」进 `attributes.vue`，那是某个类型下的属性列表，列是 属性ID / 所属类型ID / 属性名称 / 是否筛选 / 操作。

典型用法是先搭骨架再上货：运营新建「手机」类型 → 进它的属性页加「颜色」（可筛选）、「内存」（可筛选）、「容量」（不可筛选）→ 上架商品时把这些属性选成规格。`is_filter` 就是买家列表页那排筛选条件的开关：开着才出现在筛选栏，关了不出现，新增和编辑都能改。

## 撑不住的时候

这五个删除接口原来都是直接 `removeById` —— 被引用时数据库抛外键异常，前端只能弹出兜底那句「数据处理失败，请稍后重试」。用户看到这句话的处境是：**既不知道自己删不掉什么，也不知道该先处理哪一样**。「类型还被 3 个属性和 8 个商品引用」和「网络抖了一下」在这句话里长得完全一样。

第二个是聚合关系本身：属性列表接口 `GET /admin/attributes?typeId=` 的 typeId 是**可选参数**，不传就返回全表。这不是接口的错（别处查属性值也要用），但页面必须每次都带上它 —— 少带一次，「手机的属性页里出现食品的属性」就会当场上演，而串了之后没有任何地方会报错，只会在上架商品时让人选到不该有的规格。

## 改了什么

① **删之前先把引用数查出来，用中文说清**（`shared/guard/CatalogDeleteGuard`）：类型 → 「该类型下还有 N 个属性 / M 个商品，不能删除（请先迁移或删除它们）」；属性 → 「该属性已被 N 个 SKU 使用，不能删除」。返回 null 才真删。理由写在类注释里：类型/分类的「子分类、属性、商品」都是硬引用，删了存量商品就成了没归属的孤儿。

② **属性页把 typeId 钉死在路由里**：`/product-type/:typeId/attributes`，进页面就用它查列表，新增时也把它写进请求体；弹窗里「所属类型」是禁用输入框，只显示不能改 —— 属性没有「不属于任何类型」这个状态。

③ **必填就地提示，弹窗不关**：类型名不填点确定 → 「请输入类型名称」，弹窗留着、不落库；属性名同理。

④ **删除先过一道确认框**（「确认删除类型「X」？删除后不可恢复。」），确认后后端的中文原因**原样回显**到列表上，不是吞掉、也不是换成「操作失败」。

⑤ **改不动就明说**：`PUT` 走影响行数校验，0 行 = 这行在你读完之后被别人删了 → 409「记录已被删除」，不报假成功。类型和属性都没有 version 列，所以这里只认「行没了」这一种信号，不假装有版本锁。

## 凭什么证明好了

`e2e/tests/scenarios/业务/商家-商品管理/商品类型与属性.spec.js`，4 条用例，全程真点界面 + 真读库：

- **类型新增 → 改名 → 服务端复核**：新建后按名字回读库确认落库；改名后新名字在、旧名字不在。
- **必填校验**：空名点确定 → 本地提示「请输入类型名称」可见，且弹窗**仍然可见**（没被连带关掉）。
- **属性聚合于类型**：给 A 类型加两个属性（`is_filter` 一个 1 一个 0）→ 库里回读分别是 1 / 0，列表列显示「是」/「否」；改名同时关掉筛选 → 库里变 0；最后打开 B 类型的属性页，断言 A 的属性名字**不出现**。
- **删除守卫四条**：种子「手机」类型（有属性也有商品）删不掉并回显「不能删除」；新建的空类型能删掉；被 SKU 规格值用过的属性删不掉；新建的空属性能删掉。

## 附：口径与边界

- **「属性只属于当前类型」是靠页面每次带 typeId 撑住的**，不是数据库强制：`attribute.type_id` 有值，但列表接口允许不带它。所以这条规则的证据是「B 类型属性页看不到 A 的属性」那条断言，而不是约束本身。
- **`is_filter` 只影响买家筛选栏**：它不参与规格生成，也不影响价格与库存。
- **被 SKU 用过的属性删不掉是刻意的**：规格值是商品骨架的一部分，删了存量 SKU 就丢了那一维。
- **类型改名不影响存量商品**：商品只存 `type_id`，名字改了归属不变。
- **本页数字出处**：三条删除文案来自 `CatalogDeleteGuard`；「请输入类型名称」来自 `product-type/index.vue` 的 rules；「是 / 否」列来自 `attributes.vue` 的 el-tag 渲染。「类型下到底几个属性几个商品」随演示数据漂移，正文一律写成 N / M 占位，不写具体数。
