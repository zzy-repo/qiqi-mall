**这一页只有两个数字，但它是一行全局配置** —— 保存是覆盖同一行，谁改了所有人都受影响。而这两个数目前只被**存下和回显**，「到期自动关单 / 到期自动确认收货」还没有任何任务真的去执行。

## 场景

后台 `admin-web/src/views/order-setting/index.vue`：两个数字框，一个是「发货后 N 天自动确认收货」（`autoConfirmDays`），一个是「下单后 N 分钟未付款自动关闭订单」（`autoCloseMinutes`），加一个「保存」。进页面就把后端的当前值回显出来。

## 撑不住的时候

**① 它是覆盖，不是追加。** `PUT /admin/order-setting` 是纯 upsert：有那一行就改它，没有就插一条。所以「保存」的语义是「把全系统的规则改成这个」，不是「新增一条策略」。把它当列表理解，就会以为多保存几次能多出几条规则来。

**② 服务端零校验。** `update` 不校验范围、不校验空，连影响行数都刻意不查（注释写了理由：0 行只可能是那一行刚好被并发删掉，下一次 GET/PUT 会自动插回，属幂等无害，报 409 反而会让「改个自动收货天数」变成随机失败）。所以下限、取整、必填这三项**全部只由表单组件当场拦住** —— 换个入口把负数或空值写进去，后端会照收。

**③ 配好了，但闭环没接上。** 全仓的定时任务只有两个：库存展示缓存回写（`StockCacheRefresher`）和审核策略的调度（`AuditScheduleJob`）。没有任何任务读这两个数字去关单或确认收货。所以这一页是「配置生效在存储和回显层面」，不是「到期就会自动处理」。别跟人说过期会自动关单。

## 规矩落在哪

① **全局只有一行**：读接口取第一条、没有就返回空对象（表单给默认值）；写接口有则改、无则插，永远不新增第二条。

② **下限是 1，由组件落实**：`el-input-number` 带 `min=1`、`precision=0`。填 0 或负数，失焦后自动改成 **1**，**不弹提示、不报错** —— 它不把你输入的东西当成错误，只是不允许它低于下限。

③ **小数取整**：`precision=0` 会把 3.7 收成 4。所以「半天」这种需求在这一页表达不出来。

④ **字母进不去**：数字框的 `type=number` 会直接吞掉非数字字符，框变空。不是报错，是内容消失了 —— 然后失焦时按必填抱怨。

⑤ **空着点保存被前端拦住**：提示「请输入自动收货天数 / 请输入自动关单分钟数」，**请求根本不发**，后端配置一个字都不改。

⑥ **保存成功后就地刷新**：提示「保存成功」，刷新页面或下次进来回显的就是新值 —— 值的来源只有那一条记录，没有前端缓存兜底。

## 凭什么证明好了

`e2e/tests/scenarios/业务/商家-基础配置/订单设置.spec.js`，一条用例 9 步，把两个数字框的边界全走一遍：

① 页面回显的两个值**恰好等于**只读接口读到的值，且都不小于 1；两句说明文案（「发货后 N 天自动确认收货」「下单后 N 分钟未付款自动关闭订单」）在页面上。
② 改成 15 / 45 保存 → 提示成功 → **刷新页面**仍是 15 / 45 → 接口复核也是 15 / 45，且 `id === 1`（证明是覆盖同一行，不是新插一条）。
③④ 填 0、填 −5 → 输入框里都变成 `1`，且**没有任何校验错误提示**。
⑤ 填 3.7 → 输入框变 `4`。
⑥ 输入字母 → 输入框为空；失焦后提示「请输入自动收货天数」。
⑦ 空着点保存 → 仍是必填提示；再查接口，后端还是第 ② 步的 15 / 45（证明这一步真的没提交）。
⑧ 恢复基线值并保存 → 页面与后端都回到基线。
⑨ 分钟框同样受下限约束（0 → 1）—— 不只测天数那一半。

这条 spec 在 `beforeEach` 记下基线、`afterEach` **无论成败都恢复**：全局单行配置，任何人都不该被它改脏。

## 附：口径与边界

- **「自动」目前只是两个数字**：没有读它们的定时任务。这一条是本页最容易被误传的地方，所以写在正文而不是脚注里。
- **下限纠正不是校验失败**：0 / 负数被改成 1 时没有提示、没有错误态。如果你需要「拒绝负数并告诉用户」，这一页现在给不了。
- **覆盖语义的代价**：两个人同时改，后保存的覆盖前一个，不会有冲突提示（这一页没有 `version`，也没有 409）。
- **取整方向按组件的 `precision=0`**：3.7 → 4，不是「向下取整到 3」。
- **本页数字出处**：字段名与 upsert 逻辑来自 `OrderSettingController`（含「刻意不检查影响行数」的注释）；`min=1 / precision=0 / required` 与三条提示文案来自 `order-setting/index.vue` 与 spec 的 `support/admin-ui-config.js`；「没有任务执行」来自对 `@Scheduled` / `@EnableScheduling` 的全仓检索结果（只有 `StockCacheRefresher` 与 `AuditScheduleJob` 两处）。15 / 45 是那轮用例写进去的值，`id=1` 是单行配置的主键。
