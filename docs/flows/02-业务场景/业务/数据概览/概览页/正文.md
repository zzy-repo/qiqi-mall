**只回答一个问题：今天有没有事要我处理** —— 六张指标卡里三张是待办（待审核 / 待发货 / 待处理退货），三张是背景（今日成交额 / 今日订单 / 商品总数）。剩下的三张图和一张库存告警，都是为了让「异常」自己跳出来。

## 场景

后台「数据概览」页（`admin-web/src/views/dashboard/index.vue`），进后台的默认落地页。

一次请求拿完整页：`GET /admin/dashboard/overview` 返回指标卡 + 近 7 天趋势 + 订单状态分布 + 热销 Top 5 + 库存告警。页面不为每块单独发请求，也不做局部刷新。

## 撑不住的时候

**① 「今日成交额」的口径和直觉不一样，而它决定别人怎么理解这个店。** 它按 `payment_time` 落在今天、且状态属于 **1 已付款 / 2 已发货 / 3 已完成 / 7 待审核 / 8 待发货 / 9 部分发货** 来算 —— 也就是说**刚付完还没审的单已经算进成交额了**；而 **5 退款中 / 6 已退款不算**（钱要退回去了），0 待付款 / 4 已关闭也不算。看的人如果按「已完成才算成交」去理解，每天都会觉得这个数偏高——而它其实一直是同一套口径。

**② 某块没数据时，画空白和报错都是错的。** 演示库刚重置、或某个新店还没有成交时，趋势图是没有点的。此时画一块白，看的人分不清是「没生意」还是「页面坏了」；抛个错，整页都跟着像挂了一样。所以没数据要显式显示占位。

## 规矩落在哪

① **六张卡各有一个稳定的 testid**：`today-amount` / `today-orders` / `products` / `pending-audit` / `pending-ship` / `pending-return`。每张都必须有非空数字（用例断言卡片文本含 `\d`），不是空壳。

② **趋势是最近 7 天（含今天），双轴**：订单数 + 成交额，同样按 `payment_time` 归日。

③ **状态分布是全部订单按 `status` 分组**（不是只统计今天），环形图。

④ **热销 Top 5 从 `order_item` 聚合**（按商品名取前 5），不是按 SKU。

⑤ **库存告警的判据是 `sku.stock <= 10`，最多 5 条**。阈值写在 `AdminDashboardController.STOCK_ALERT_THRESHOLD`，行的条数必须与接口返回的 `stockAlerts` 长度一致。

⑥ **每个异常都能接着干活**：待审核 / 待发货多 → 去订单列表；库存偏低 → 去 SKU 页补库存；有待处理退货 → 去退货申请页。看数不是目的，发现异常才是 —— 所以这一页的价值是「一眼看完，知道下一步点哪儿」。

⑦ **服务端直接聚合真实表**：数据量在几千行级别，不引入缓存、不引入定时任务。所以刷新就有最新的数，也没有「缓存还没过期」这种解释。

## 附：口径与边界

- **「今日」按 `payment_time` 归日，不按创建时间**：所以一笔昨天下单、今天付款的单算今天的成交。
- **成交额含待审核**：这不是 bug，是「已付款且未退款」这条口径的直接结果（`DEAL_STATUSES` 六个状态）。要「已完成才算」的口径，这一页现在给不了。
- **库存告警看的是 `sku.stock`（展示缓存），不是分桶权威值**：分桶模式下这个字段由后台任务按 `SUM(桶)` 每 250ms 回写，所以它可能比真实可用量滞后一小会儿。要看权威值得去库存对账。
- **告警最多 5 条**：低于阈值的规格比 5 个多时，页面只列前 5 条 —— 这不是「只有 5 个」，别当成全量清单用。
- **没有时间范围选择器**：7 天是写死的，这一页不做「近 30 天 / 自定义区间」。
- **本页数字出处**：`DEAL_STATUSES = [1,2,3,7,8,9]`、`STOCK_ALERT_THRESHOLD = 10`、7 天、Top 5、告警最多 5 条都来自 `AdminDashboardController` 的常量与类注释；六个 testid 与占位行为来自 `dashboard/index.vue` 与 spec 的断言。具体金额与单数随库变化，正文不写绝对数。
