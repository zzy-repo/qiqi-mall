## 注册与登录（registration / login）

买家侧只有一个认证页（`portal-web/src/views/login/index.vue`），「登录」与「注册」是同一页的两个页签：注册填用户名、密码，昵称与手机号选填，昵称为空时落用户名；登录只要用户名与密码。

校验分三层，顺序固定。第一层是表单规则 `required`：用户名或密码为空就地提示「请输入用户名 / 请输入密码」，请求都不发。第二层是路由守卫：`checkout` / `orders` / `addresses` 三条路由带 `requiresAuth`，`beforeEach` 拿不到令牌就返回 `{ path: '/login', query: { redirect: to.fullPath } }`。第三层是后端 `PortalAuthController` 的三个出口：空值 → 400「用户名和密码不能为空」；用户名已存在 → 400「用户名已被占用」；密码不对、账号被禁用、或该账号密码为空 → 401「用户名或密码错误」。401 不区分原因，同一句话覆盖三种情况。

注册成功即登录：`register` 建档后直接返回令牌，建号与发令牌一趟完成，不再要求输一遍密码。密码以 `PasswordEncoder` 哈希落库，`status` 置 1。

回跳只认 `redirect` 一个参数：守卫把原始 `fullPath` 编进 query，登录成功后 `router.replace(redirect)`，取不到字符串时回 `/`。登录态是本地令牌（`localStorage` 的 `qiqi_member_token`），不是 Cookie 会话。认证成功后先合并本地购物车再回跳，合并件数大于 0 时提示一句，合并失败不阻断登录。

**验证**　`注册与登录.spec.js`：6 条用例、23 处断言，真点界面，不 mock 接口。断言要点按用例列：① 注册成功即登录 —— 离开登录页、顶栏出现退出入口与昵称、首页商品卡片图全部实际加载，再用页面上的令牌反查 `profile`，用户名与昵称与填入一致、`status=1`；② 重名 —— 先真注册一个同账号再提交注册，提示含「用户名已被占用」且 URL 仍停在 `/login`；③ 必填 —— 空表单提交出现两条字段提示，登录与注册两个页签各测一遍，只填用户名仍过不去；④ 密码错 —— 提示含「用户名或密码错误」，同账号换回正确密码立刻能进，说明拒绝的是这一次凭据而不是锁号；⑤ 未登录访问受保护页 —— 打开 `/addresses` 落到 `/login?redirect=…addresses`，登录后回到 `/addresses` 且「收货地址」标题可见；⑥ 密码强度现状 —— 1 位密码注册成功，这条用例用来钉住现状。

**边界**　现状没有密码强度校验：后端只判空与重名，「1」也能注册；这一条写在用例里，加了强度校验它就会红，文档与用例要同步改。没有失败次数限制、没有图形验证码、没有找回密码：登录失败只落一条 `member login fail: … reason=bad-credential-or-disabled` 的 warn 日志（带用户名与 IP），不锁号、不限流。管理端登录有验证码，买家侧没有，两边口径不同，不互相类推。`redirect` 是纯前端行为，拼接与读取都在路由表与登录页里，服务端不参与，它挡误入、不构成越权控制。令牌在 `localStorage`，另一个标签页退出不会立刻踢掉本页，要等下一次请求才失效。本页没有性能数字：内容是几条规矩与几个明写的缺口。
