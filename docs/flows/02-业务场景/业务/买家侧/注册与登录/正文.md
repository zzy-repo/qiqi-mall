**门口守严，回头路别丢** —— 注册即登录（不让人刚注册完再输一遍密码）；未登录点「我的订单 / 结算 / 收货地址」被拦到登录页时，`redirect` 记住他本来要去哪，登录完自己跳回去。

## 场景

登录和注册是同一个页面的两个页签（`portal-web/src/views/login/index.vue`）。注册要填用户名、密码，昵称和手机号选填；登录只要用户名和密码。

三道门是客户端路由守卫在做：`router/index.js` 里 `checkout` / `orders` / `addresses` 三条路由带 `requiresAuth`，`beforeEach` 见到没有令牌就返回 `{ path: '/login', query: { redirect: to.fullPath } }`。所以「去结算时被拦住」不是弹窗，是换页 —— 而换页最容易丢掉的正是「我原来要去哪」。

后端只有三个出口（`PortalAuthController`）：账号密码为空 → 400 `用户名和密码不能为空`；用户名已存在 → 400 `用户名已被占用`；账号密码不对或账号被禁用 → 401 `用户名或密码错误`。注册成功直接返回登录态，建号和发令牌一趟完成。

## 规矩落在哪

① **空值前端先拦，后端再拦一次**。前端是为了不让人白等一次往返（就地提示、请求都不发），后端是因为前端校验永远不算数 —— 直连接口时 400 还得回同一句话。

② **重名当场拒，人停在注册页**，输入的内容不清空，改个名字就能再提交。

③ **注册即登录**：这是产品口径，不是省事 —— 刚注册完又要再输一遍密码，人会跑掉一半。

④ **回跳只认 `redirect` 这一个参数**：`/login?redirect=%2Faddresses` 登录成功后直接去 `/addresses`，不是一律回首页。

## 凭什么证明好了

`e2e/tests/scenarios/业务/买家侧/注册与登录.spec.js`，6 条用例、23 条断言，全程真点界面：

- **注册成功即登录**：注册后离开登录页、顶栏出现「退出」入口与昵称、首页商品卡片图真加载；再用页面上的令牌反查 `profile`，用户名/昵称与刚填的一致、`status=1` 启用。
- **重名**：先真注册一个账号，再用同名注册 → 页面出现错误提示且含 `用户名已被占用`、URL 仍在登录页。
- **必填**：什么都不填就点提交 → 字段下出现 `请输入用户名` / `请输入密码`，URL 仍停在 `/login`；登录与注册**两个页签都有**这套校验，只填用户名也过不去。
- **密码错**：错误密码 → `用户名或密码错误`，停在登录页；同一个账号换回正确密码立刻能进，证明拒绝的是这一次凭据而不是把账号锁了。
- **未登录访问受保护页**：直接开 `/addresses` → 被重定向到 `/login?redirect=…addresses`，登录后回到 `/addresses` 且「收货地址」标题可见。
- **密码强度现状**：1 位密码也能注册成功 —— 这条是**故意用来钉现状的**，哪天加了强度校验，它会红，提醒同步改文档和用例。

## 附：口径与边界

- **现状就是没有密码强度校验**：后端 `register` 只判空和重名，所以「1」也能注册。这不是本页偷偷省略的部分，是明写在用例里的待补口子。
- **没有失败次数限制、没有图形验证码**：登录失败只落一条 `member login fail: … reason=bad-credential-or-disabled` 的 warn 日志（带用户名与 IP），不做锁号、不做限流。管理端登录有验证码（见 `账号与会员/管理员登录与验证码`），买家侧没有 —— 两边口径不同，别互相类推。
- **登录态是本地令牌**（`localStorage` 的 `qiqi_member_token`），不是 Cookie 会话：所以「另一个标签页退出」不会立刻踢掉这一页，要等它下一次请求才失效。
- **没有找回密码**：登录页只有「登录 / 注册」两个页签，忘了密码只能换账号（现状，未做）。`redirect` 也纯是前端行为 —— 拼接与读取都在 `router/index.js` 和登录页里，服务端不参与。
- **本页机制简单，没有事故可讲**：它的价值在于几条容易写错的规则（空值两层拦 / 重名当场拒 / 注册即登录 / `redirect` 回跳），以及两个明写的现状缺口（无密码强度校验、无失败次数限制）—— 这一页薄是内容本身薄，不是没写。
