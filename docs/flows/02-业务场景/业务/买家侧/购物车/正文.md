## 购物车（cart）

购物车是意图清单，不是账务数据。同一个规格再加一次只累加数量、不新增行：`POST /portal/cart` 先按「会员 + 规格」查一次，查到就 `quantity` 加上去，查不到才 `save`，所以一个规格永远一行，合计跟着数量走。

数量下限是 1，两处兜：前端 `el-input-number` 写 `:min="1"`（减到 1 就停），后端 `add` 与 `updateQuantity` 各自纠正 `qty < 1 ? 1 : qty`，手工输 `-5` 也会回到 1，不存在「零件商品」。这一层不校验库存：库存 2 件时车里存 3 件是允许的，超量只在下单那一刻失败 —— 天天查库存既慢又没意义。顺着这个定性还有一条：`cart` 表没有 `version` 列，加购与改数量遇到影响 0 行（同账号另一端刚好把这行删了）刻意不报错，因为这里改错不会让任何人多花钱，账务口径在结算与订单那边。

未登录也能加购：行存在 `localStorage` 的 `qiqi_local_cart`，页面顶上标一句「（未登录，暂存在本浏览器）」；登录成功后调 `POST /portal/cart/merge`，逐条按「会员 + 规格」累加或新建、返回合并条数，合并完清掉本地；规格已被删的条目直接跳过，不中断整批。未登录点「去结算」不硬拦，跳 `/login?redirect=%2Fcheckout`，登录完自己回来。价格不在车里：只存规格 id 与数量，价格每次 `list()` 现取 `sku.price`。

**验证**　`购物车.spec.js`：4 条用例、23 处断言，真点界面 + 读库。累加与改数量：连点两次加购 → 行数仍是 1、库里 `quantity=2`、页面合计等于单价 × 2；改成 3 后库里是 3、合计跟着变；删除后行数与合计一起清掉。数量边界与超库存：连点三次减号停在 1，手工输 `-5` 回到 1；后台把库存压到 2 后车里放 3 件允许落库，去结算提交出现错误提示、URL 仍在 `/checkout`、不产生订单、库存仍是 2、车里那一条还在（失败不吞购物车）。匿名加购与登录合并：未登录加购后本地键有值、页面标着「未登录」，登录后本地键被清成 `null`、云端购物车恰好 1 行 1 件。未登录去结算：URL 必须匹配 `/login?redirect=…checkout`。

**边界**　顶栏角标只在路由变化或整页重载时重算（`watch(route.fullPath)` 加 `onMounted`），所以「车里 1 行 2 件已删空、角标还停在 2」会短暂同框，这是现状，用例不拿角标当断言点。合并是尽力而为：单条 0 行不中断整批，也不回滚已合并的条目，最多是某一条没进来。车不回写价格，商家改价后车里的小计立刻变，这与订单明细的价格快照是两套口径。下架商品在车里不会自动消失：这一层不看 `publish_status`，要清理得靠人删或等下单失败。「全选结算」在现有实现里不存在，所以用例不假装能测 —— 没做与没测是两件事。
