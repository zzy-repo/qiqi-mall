**购物车是「意图清单」，不是账务数据** —— 同一个规格再加一次只累加数量不新增行；数量下限是 1；库存这一层**故意不校验**，留给下单那一刻才算数；没登录也能加购，登录时把本地那些并进账号并如实告诉人并了几件。

## 场景

买家从商品详情点「加入购物车」，落到 `portal-web/src/views/cart/index.vue`：表格只有商品 / 规格 / 单价 / 数量 / 小计 / 操作六列，底部是合计与「去结算」。

这一页没有「勾选」列 —— 全选结算这个行为在现有实现里根本不存在，这条覆盖点无实现可测，所以用例里也不假装能测（要说清「没做」和「没测」的区别）。

## 规矩落在哪

① **同规格累加，不新增行**：`POST /portal/cart` 先按「会员 + 规格」查一次，查到就把 `quantity` 加上去，查不到才 `save`。所以车里永远一个规格一行，合计跟着数量走。

② **数量下限是 1，两处兜**：前端 `el-input-number` 写 `:min="1"`（点减号到 1 就停），后端 `add` 与 `updateQuantity` 各自都写 `qty == null || qty < 1 ? 1 : qty` —— 手工输 `-5` 也会被纠正回 1。不存在「零件商品」这种行。

③ **这一层不校验库存**：库存 2 件时车里存 3 件是允许的，超量只在下单那一刻失败。理由写在代码注释里：购物车是意图清单，天天查库存既慢又没意义 —— 而且它接着做了个更彻底的选择：`cart` 表**没有 version 列**，加购/改数量遇到「影响 0 行」（同账号另一端刚好把这行删了）**刻意不报错**。因为这里改错了不会让任何人多花钱，账务口径在结算与订单那边。

④ **匿名也能加购，登录时合并**：未登录时行存在 `localStorage` 的 `qiqi_local_cart`（`utils/localCart.js`），页面顶上标一句「（未登录，暂存在本浏览器）」；登录成功后调 `POST /portal/cart/merge`，逐条按「会员 + 规格」累加或新建，**返回合并条数**，合并完清掉本地。规格已不存在（被删）的条目直接跳过，不中断整批。

⑤ **未登录点「去结算」不硬拦**：跳 `/login?redirect=%2Fcheckout`，登录完自己回来。

## 凭什么证明好了

`e2e/tests/scenarios/业务/买家侧/购物车.spec.js`，4 条用例、23 条断言：

- **累加 / 改数量 / 删除**：连点两次加购 → **行数仍是 1**、库里 `quantity=2`、页面合计等于单价 × 2；改成 3 后库里是 3、合计跟着变；删除后行数与合计一起清掉。
- **数量边界 + 超库存**：连点三次减号 → 停在 1；手工输 `-5` → 回到 1；后台把库存压到 2 后车里放 3 件**允许落库**，去结算提交 → 出现错误提示、URL 仍在 `/checkout`、**不产生订单**、**库存仍是 2**、车里那一条**还在**（失败不吞购物车）。
- **匿名加购 → 登录合并**：未登录加购后本地 `qiqi_local_cart` 有值、页面标着「未登录」；登录后本地键被清成 `null`、云端购物车恰好 1 行 1 件。
- **未登录去结算**：URL 必须匹配 `/login?redirect=…checkout`。

## 附：口径与边界

- **顶栏角标会短暂对不上**：它只在路由变化 / 整页重载时重算（layout 里 `watch(route.fullPath)` + `onMounted`），所以「车里 1 行 2 件被删空、角标还停在 2」会短暂同框。这是现状，用例不拿角标当断言点。
- **合并是「尽力而为」**：单条 0 行不中断整批，也不回滚已合并的条目 —— 合并失败不会让人丢东西，最多是某一条没进来。
- **购物车不回写价格**：它存的是规格 id + 数量，价格每次 `list()` 现取 `sku.price`。所以商家改价后车里的小计立刻变 —— 这与订单明细的价格快照是两套口径，别混。
- **下架商品在车里不会自动消失**：这一层不看 `publish_status`（见 `业务/买家侧/商品浏览与搜索` 的附注）。要清理得靠人去删，或者等下单环节失败。
