**573 万行孤儿不是"数据脏"，是一条 reset 少删了三张表** —— 压测每轮开跑前都会删掉自己造的订单，但只追加的三张状态台账没跟着走；一天下来订单状态台账堆到 **5,717,917 行**，把台账查询页拖到 **25 秒**才打开。

## 场景

压测脚本（`bench/tools/prepare.sh`）的 reset 语义是"只删自己造的"：按测试会员（`username like 'lg\_%'`）圈出订单，再逐级删 包裹 → 发货单 → 明细 → 支付流水 → 订单，最后把库存写回 50 万。

库里另一类表是**只追加**的证据表：订单状态台账、包裹状态台账、售后台账、库存台账、后台操作审计、支付流水。它们记的是"这件事发生过"，因此删业务主表时**不会**跟着消失 —— 删它们只能由删单那段代码自己负责，这正是这次漏掉的地方。

## 撑不住的时候（事故经过）

- reset 删了 9 张业务表，**漏了 3 张状态台账**（`order_status_ledger` / `delivery_status_ledger` / `return_status_ledger`）。订单被删、台账留着 → 孤儿行。
- 每轮压测的审核、发货、取消都会写台账，一轮留下 **30 万~70 万行**（量级，由压测轮次与台账行数的对照得出，没有逐轮复测）。
- 一天下来订单状态台账 **5,717,917 行**，其中 **5,717,908 行**的 `order_id` 已经不存在：总数减去属于真实订单的那 **9 行**（差集算法，不是另一次抽样）。这 9 行就是"不许清空整表"的直接原因 —— 清空会把真单的台账一起切掉。
- 症状：台账查询页打上去要等 **25 秒**，人以为挂了；而所有接口、所有业务功能都正常，监控也全绿。
- 出处：`bench/tools/prepare.sh` 第 237 行的事故注释原文——"2026-11-14 事故：这三张漏删，单日堆到 5,717,917 行孤儿，/admin/ledgers 挂 25s"。

## 改了什么

① **清孤儿：一次性、分批、可中断**。条件是"`order_id` 已不存在 且 `created_at` 不早于当天 02:00"，**29 批 × 20 万行，116 秒**删完。为什么带时间条件：02:00 之前的孤儿是更早的遗留、不属于这次事故 —— 顺手一起清别人的数据，本身就是第二起事故。

② **修 reset 脚本**：三张台账改成**按订单 id 删**（`… where order_id in (select id from lg_o)`），**不许 `TRUNCATE` 全表**。台账是证据表，全清会把真实订单的 9 行一起删掉；脚本注释里就写着这句"台账是证据表，可能含非压测订单/历史行"。

③ **加台账孤儿自检**：reset 跑完必须打出「台账残留(应为 0)=0」这一行。

④ 两个坑写进脚本注释，因为它们都"看起来正常"：

- **坑一**：自检最初写成一条语句里**三次引用同一个临时表**（`lg_o`），MySQL 直接 **ERROR 1137**；改成把三张台账 UNION 起来、只引用一次才对。
- **坑二**：执行函数是 `mysql … 2>/dev/null`，**stderr 被丢弃** —— 报错不会出现在屏幕上，那条自检就**静默没有输出**。所以口径必须写成：**自检行缺失 = 失败**，不是"没报错就算通过"。这一条比第一条更危险，因为它把"没查"伪装成"查过了没问题"。

位置：`bench/tools/prepare.sh`（reset 段 + 237 行事故注释 + 1137 那条注释）、`scripts/check-data-integrity.sh` 第 ① 项（孤儿台账体检，只读、退出码可当门禁）。

## 附：口径与边界

- **「孤儿」的定义只看父行在不在**（`order_id` 不在订单表里），与时间无关；时间条件只用于**这次清理的范围**，不进入定义。
- **台账能按 id 删，不能清空**：全清会连真单的台账一起切掉，事后无法回答"当时谁把它改成了什么"。这就是 ② 的全部理由。
- **三条自检红线**：① 一条语句里同一张临时表只能引用一次（否则 ERROR 1137）；② `sql_db` 吞 stderr，报错不会出现在输出里；③ 所以"没输出"必须当失败 —— **自检行缺失 = 失败**。
- **体检与清理必须分开**：`check-data-integrity.sh` 只发 SELECT（可随时、反复、在任何人手上跑）；清理前先 dump。把两件事揉进一条命令，就再也没人敢随手跑它了。
- **数字出处与复测状态**：5,717,917 与 25 秒 → `bench/tools/prepare.sh:237`；5,717,908 → 差集推导（总数 − 真实订单台账 9 行，9 行可由体检第 ⑥ 项在 `qiqi_mall_test` 上直接看到）；每轮 30~70 万行 → 量级，未逐轮复测；29 批 × 20 万 / 116 秒 / 0.059 秒 / 791 = 76+27+15+640+27+6 → 当晚会话记录，本次未复测。
