**"后面有断言"不等于"断言断的是这一步的产物"** —— 一次"零风险"的批量删除，删掉的是 e2e 里 78 处固定等待，理由只有一句"后面有断言"。可断言断的如果是上一步留下的旧数据，那些等待一去掉，假绿就长出来了。

## 场景

e2e 里有大量固定等待（`waitForTimeout`），它们等的是**异步产物**：列表刷新后的新行、toast 出现、抽屉里的数据到位。这些等待是"慢"，所以一直有人想删。

这一轮真去删了：**93 处**里删掉 **78 处**，判定依据是"后面有断言兜着"。删完这一批之后，问题出现了 —— 不是"跑红"，而是**可能永远绿**。

## 撑不住的时候（事故经过）

判据错在哪儿：`sleep` 后面确实有断言，但没人证明过**断言断的是上一步动作的异步产物**。去掉等待之后，两个结果都是坏的：

- **假绿**：上一步留下的旧数据也满足断言 → 用例永远绿，被测行为坏了也看不出来。最典型的形状是"松断言"：查 0 行被当成有 1 行（`group_concat` 没命中时返回的是字符串 `NULL`，`rows.length` 于是等于 1 —— 这一条在 `后台操作审计.spec.js` 里真的撞过，注释里就写着"松断言就是这么假绿的"）。
- **偶发红**：断言恰好落在刷新之前那一瞬间 → flaky，而 flaky 的常见处置是"再跑一次"，于是门禁被噪声驯化。

也就是说：**78 处不是"删错了几行"，是把一整批用例的判别力换成了"看起来在跑"**。所以 78 处全部回滚。

## 改了什么

① **重判三类**（判据不是"后面有没有断言"，而是"断言的对象是不是异步产物"）：

| 类 | 数量 | 判据 | 处置 |
| --- | --- | --- | --- |
| **A** 真静态可删 | 8 | 断言的对象是**静态事实**（页面标题、固定文案），且断言 API 自己会轮询（`toContainText` / `toBeVisible`） | 删，且**不新增假绿**（本来就断得到） |
| **B** 需要改造 | 72 | 断言的对象是**异步产物**（列表行数、金额、状态、抽屉数据） | 先把固定等待换成"轮询到条件成立"（`expect.poll`），再谈删 |
| **C** 不能动 | 13 | 删了会改变时序语义，或需要先另造一个可观测条件 | 保留，并在注释里写清"为什么这里必须等" |

A 类的判据长什么样，仓库里有落款（`e2e/tests/support/catalog-ui.js`）："断静态标题，`toContainText` 自带轮询 → 固定 sleep 多余"。反过来，C/待改类型的落款在 `后台操作审计.spec.js`："删掉前面的 sleep 不会新增假绿（本来就断不到）……真正想等「筛选生效」应改成 `expect.poll(() => 行数/首行文本变化)`"。

② **把验证方法固化成四步标准动作**（`bench/README.md` 第 10 节"验证「删等待」类改动的标准动作"）：

1. 先 `grep` 被改 helper 的**所有调用方**（support 的改动波及所有 spec，漏一个就只证明了半个入口）；
2. **独占一个 shard**（`bench-lock.sh` + `pgrep -f playwright` 确认没有别的跑批）；
3. 同一 shard 上 `--repeat-each=20 --workers=1`（别加 worker：并发本身会制造新的互相干扰）；
4. **判据是零失败**：任何一次红都算"该处不成立"，把等待从 git 原值恢复，**不许为了让绿去改断言或放宽 timeout**。

## 凭什么证明好了

这条改动的证据只能是**重复执行的计数**，界面演不出来（假绿的现场就是"什么都没发生"），所以不录视频。

- 本轮验证：**27 条用例 × 3 遍 = 81/81 全绿，0 flaky**，在独占 shard 上跑（不是加大超时，也不是 rerun 到绿）。
- 判据与命令（仓库里的标准动作，`bench/README.md` 第 10 节）：

```
/root/.qiqi-standing/bench-lock.sh acquire e2e-repeat-each
pgrep -f playwright || true          # 有别的跑批就等它结束，别强开
cd /root/qiqi-mall && E2E_SHARD_FROM=1 E2E_SHARDS=1 E2E_WORKERS=1 \
  bash scripts/e2e-run.sh <覆盖到的 spec 文件...> --repeat-each=20 --workers=1
/root/.qiqi-standing/bench-lock.sh release
```

- **81/81 是当晚会话的记录，本轮未复测**（复测要跑 81 条、几分钟起步，且会和别的跑批抢库）；上面这条命令任何人都能重跑出同一口径的数字。
- 能直接查的现状（今天 `grep -rc waitForTimeout e2e/tests`，把注释里提到的也算进去了）：scenarios 下 **180** 处、support 下 **129** 处 —— 说明这一轮的目标**不是把等待清零**，而是"不许把等异步产物的等待当成可删"。

## 附：口径与边界

- **可删的不是"等待"本身，是"等一个必然已经成立的静态事实"**。同一句 `waitForTimeout(1000)`，在断言静态标题后面是纯浪费，在断言异步列表后面是判别力 —— 长得一样，语义完全不同。
- **A/B/C 的分界不是主观判断，是可操作判据**：断言对象是不是异步产物？断言 API 有没有自带轮询？删了之后"旧数据"会不会也满足？
- **"跑一次绿"不构成证据**：竞态窗口是概率性的，一次通过只证明"这次没踩上"。这也是为什么判据必须是"重复 N 遍零失败"，而不是"我本地绿了"。
- **回滚不是失败，是判据生效**：78 处回滚是这一轮最有价值的产出 —— 它把"零风险可删"这个结论当场证伪了。
- **未复测**：93/78/8/72/13 这几个数字来自当晚会话；`--repeat-each` 的四步与命令、A 类与待改类的注释落款都在仓库里（`bench/README.md` 第 10 节、`support/catalog-ui.js`、`台账七类/后台操作审计.spec.js`），可逐条对照。
