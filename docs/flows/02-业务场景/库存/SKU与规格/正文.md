**卖的是规格，不是商品** —— 商品只是壳，能下单的是一行 `sku`：颜色 + 内存一个组合一行，价格、库存、图都挂在这一行上；规格值也不是自由文本，而是 `sku_spec(attribute_id, value)`，同一个 SKU 同一个属性只能有一个值。

## 场景

商家在商品列表某一行点「SKU」进入 `admin-web/src/views/product/skus.vue`。弹窗里一行规格 = 一个属性下拉 + 一个值输入（`sku-form-spec-attr` / `sku-form-spec-value`），再加价格、库存、SKU 图。列表上那串「颜色:黑色,内存:256G」**不是存的字段**，是 `SpecTextHelper#buildText` 按 `attribute.name` 现拼出来的。

为什么库存挂在 SKU 上、不挂在商品上：库存的粒度就是「可售组合」的粒度。一个商品有四个组合，买家问的是「我要的那个组合还有没有」，不是「这个商品还有没有」。所以 `sku.stock` 是规格级一列，`sku_bucket.sku_id` 也是规格级，商品表上根本没有库存这个字段。

页面上只有三个动作：新增（选属性 + 填值）、编辑（整组替换规格值 / 改价格库存）、删除（被引用时拒）。C 端详情页那排规格按钮、切换时价格与库存跟着变，读的就是这里填的东西。

## 撑不住的时候

撑不住的不是这个页面，是**「一份库存就是一个 int」这个存储模型**。三条都在别处量到过：

- **写模型：一份库存只有一行。** 扣减要改的永远是同一行 `sku`，同一规格的所有并发都排在这一把行锁上 —— 加核、加连接都不动它（`库存/库存分桶`：同一台机、同一镜像，并发 8→16，单行吞吐 298.9 → 300.6 ok/s，每单等锁 30.0 → 84.3 ms）。要拆开这份库存，前提是「库存属于 SKU」先说清；挂到商品上或挂到订单明细上，都拆不了。
- **读模型：一个字段干三份活。** `sku.stock` 同时是「裁决依据」「展示值」「后台改库存的入口」。只要它三合一，「读出来 2 件、扣 2 件、写回 0」这种写法就永远看着是对的（见 `库存/一条SQL吃掉「读、判、写」`）。分桶之后它的列注释已经写明降级：`总库存——展示缓存：由 SUM(sku_bucket.stock) 周期回写，扣减/回补不写它、也不拿它裁决`。
- **改模型：规格值必须整组替换，不能 patch。** 编辑时若按「哪行变了就更新哪行」去 diff，「把内存改成 512G」既想删旧行又想插新行，中间态就撞 `uk_sku_attribute(sku_id, attribute_id)`。所以 `SkuController#update` 里是 `sku_spec` 先 `remove` 再 `saveSpecs` 整组重写：一个属性一行，不留旧值尾巴。

## 规矩落在哪

① **规格值只能从所属类型的属性里选**，值是填的不是造的；`saveSpecs` 直接跳过 `attributeId` 为空或 `value` 空白的项，不会悄悄存一行没有属性的规格。

② **价格与库存必填**：两个框清空再点「确定」，`el-form-item__error` 就地报错、弹窗不关、库里不落行 —— 一个没价格的 SKU 摆到前台就是坑。

③ **删除先算引用，再决定**：`CatalogDeleteGuard#countOrderItemsOfSku` / `#countCartsOfSku` 两条计数 + `checkSku` 判定；`?dryRun=true` 只预演不落库，把「将删除哪个 SKU（含所属商品、售价、库存），当前被 N 条订单明细、M 个购物车引用」说清楚。有引用就拒，中文原因原样回给前端。**停卖的正确动作是把整个商品下架**，不是删掉那一行 —— 删了，历史订单明细里的规格 id 就成了断掉的编号。

④ **SKU 图存相对路径**（`sku.pic`），列表缩略图、弹窗预览、C 端详情读同一个字段，没有第二份副本。

## 附：口径与边界

- **「规格组合唯一」现在靠人，不靠库**：`sku_spec` 的唯一键是 `(sku_id, attribute_id)`（一个属性一个值），`sku` 表上没有「同一商品下规格指纹唯一」这种约束。手滑配出两行一模一样的「颜色:黑,内存:256G」，库照收。这是已知缺口，不假装有。
- **`sku.stock` 是缓存**：分桶模式下由周期任务按 `SUM(sku_bucket.stock)` 回写（默认 250ms），任何拿它做扣减判断的写法都是回归；SKU 编辑里「改库存」走 `resetStock`（重铺分桶 + 标脏），不是直接写这一列。
- **规格文本不落快照**：`specText` 每次现拼，所以改属性名会连带改掉历史订单里的规格展示；真正被快照的是订单明细的商品名与单价（`order_item.product_name` / `product_price`）。
- **本页没有新测量**：引用的 298.9 / 300.6 ok/s 与 30.0 / 84.3 ms 出自 `库存/库存分桶` 那页的 A/B（2026-11-12 独占窗口），本页只引用、不复测。
