## P1 管理员发货按钮缺失

- **文档**：`docs/flows/5-场景3-订单履约.mmd` — A2「点击发货按钮 ⛔缺UI 状态改已发货」
- **现象**：`admin-web` 订单列表操作列只有「明细」「编辑」，没有任何状态流转按钮。
- **影响**：订单状态永远停在 `1 已付款`，后续确认收货、售后都无从谈起。
- **建议**：`POST /admin/orders/{id}/ship`（status 1→2）＋ 行内「发货」按钮，且只对 `status=1` 显示。

## P2 买家确认收货缺失

- **文档**：同上 — B2「确认收货 ⛔缺confirm接口」
- **现象**：`portal-web` 我的订单操作列只有「详情」「模拟支付（status=0）」「申请退货（status>=1）」，没有「确认收货」。
- **影响**：订单到不了 `3 已完成`；场景4 文档要求的「已收货订单」前提无法达成（目前只能对「已付款」订单申请退货）。
- **建议**：`POST /portal/orders/{id}/confirm`（status 2→3）＋ 按钮，仅 `status=2` 显示。

## P3 买家看不到退货审核结果

- **文档**：`docs/flows/6-场景4-售后退货.mmd` — B5「收到审核结果通知 ✅」
- **现象**：管理员审核通过后（后台列表状态正确变为「已通过」），买家「我的订单」该订单行仍是
  `QQ... ¥3999.00 已付款 ... 详情 申请退货`，没有任何退货状态/退款进度展示。
- **影响**：售后流程对买家不可见，无法闭环；文档标注的 ✅ 与实现不符。
- **建议**：`GET /portal/returns`（已有）接到买家端，在订单行或详情里展示售后状态（待处理/已通过/已拒绝）。

## P4 商品「分类」树选择点父分类不生效

- **位置**：`admin-web/src/views/product/index.vue` 商品新增/编辑弹窗
  ```html
  <el-tree-select v-model="form.categoryId" :data="categoryOptions" ... />  <!-- 缺 check-strictly -->
  ```
- **对照**：`admin-web/src/views/category/index.vue` 的父分类下拉带了 `check-strictly`，行为正常。
- **复现**：编辑商品 → 分类点「服装」（有子分类的父节点）→ 控件显示仍是原值 → 保存后数据库 `category_id` 未变（实测仍为 4）。
- **原因**：`el-tree-select` 默认 `check-strictly=false`，单选模式下点击带子节点的节点只会展开、不会选中；只有叶子节点可选。
- **影响**：无法把商品挂到有子分类的父分类上（如「手机数码」「服装」），只能选末级分类。
- **建议**：给该 `el-tree-select` 加 `check-strictly`（与商品分类页保持一致）；是否需要「只能选末级」是产品决策，若确实只允许末级，应在 UI 上明确禁用父节点而不是静默无效。

## 已确认正常的链路（测试通过）

- **场景1**：管理员上架商品（主图/相册/SKU规格值）→ 买家首页可见 → 搜索命中 → 详情页规格按钮来自 `sku_spec`、相册展示、价格随 SKU 变化。
- **场景2**：游客加购（localStorage）→ 结算拦截带 redirect → 注册即登录 → 本地购物车合并并清空 → 结算下单（快照+扣库存）→ 模拟支付 → 订单已付款；接口复核库存 -1、明细快照正确。
- **场景4 前半段**：买家申请退货（选原因+说明）→ 入库待处理 → 管理员审核通过 → 后台状态「已通过」。
